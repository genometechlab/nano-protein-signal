# nano-protein-signal

A computational framework for analyzing nanopore ionic current signals from protein translocation.

## Overview

This repository contains the analysis code for *A strategy for ionic current analysis of nanopore protein readouts*. The method was developed on the PASTOR constructs of Motone et al. (2024) [1], which are translocated through a nanopore by the ClpX motor. The code covers denoising, variable-region boundary assignment, change-point segmentation, segment feature extraction, DTW barycenter templates, LSTM classification and profile-HMM modeling.

The repository is a collection of analyses rather than a standalone software package. Each step lives in its own directory.

## Installation

The environment is managed with [uv](https://docs.astral.sh/uv/) (Python 3.12). `pyproject.toml` and `uv.lock` pin every dependency, including PyTorch for the LSTM.

```bash
git clone https://github.com/genometechlab/nano-protein-signal.git
cd nano-protein-signal
uv sync                                                  # installs all dependencies into .venv
export PYTHONPATH="$PWD:$PWD/preprocessing:$PWD/hmm"     # the repo's own code is used in place, not installed
```

Every command below assumes you're in the repository root with `PYTHONPATH` set as above, and runs through `uv run`.

The profile HMM's `yahmm` extension is compiled from Cython the first time it's imported, so a C compiler is needed (the Xcode Command Line Tools on macOS, gcc on Linux). To check the installation:

```bash
uv run python -c "import vrhmm.yahmm.yahmm, nanoclean, ruptures, tslearn, torch; print('ok')"
```

`environment.yml` and `requirements.txt` are kept for reference only. `pyproject.toml` replaces them.

## Analysis pipeline

1. **Denoising.** Three sequential passes, each reconstructing flagged samples with Huber regression:
   - Isolation Forest point anomalies (contamination 0.10);
   - total-variation smoothing;
   - CWT spike detection, flagging samples whose high-frequency spike energy exceeds its median by 0.25 × 1.4826 × MAD.
2. **Boundary assignment.** Variable regions are delimited at the absolute minimum of each YY dip.
3. **Segmentation.** Both methods use a custom variance-based cost:
   - PELT gives a variable number of segments (penalty 5, minimum segment size 30);
   - Dynp gives a fixed 35 segments (34 breakpoints).
4. **Feature extraction.** Statistical features are computed for each segment.
5. **DTW templates.** DBA barycenters are built per amino acid from the Dynp segmentations, and template–trace alignments are compared.
6. **Classification.** A bidirectional LSTM runs on segment feature sequences: 20-way, pairwise, and charge, size and polarity groups.
7. **Profile HMM.** The HMM is built from DBA barycenters, with Viterbi decoding. It's evaluated on the same trace-grouped five folds as the LSTM, with all parameters estimated from training folds only.

### HMM cross-validation and figures

These two scripts reproduce the HMM results reported in the paper and in the response to reviewers.

`hmm/hmm_cv_evaluation.py` runs:
- the Dynp-34 profile HMM in the five cross-validation folds shared with the LSTM, with one-pass Viterbi re-estimated transitions and a variance scale tuned on a grouped inner split;
- the original-transition sensitivity analysis, the summary-statistics logistic-regression baseline, the cross-context (construct) split, and the molecule sensitivity analysis.

It saves per-region predictions, the 20 per-class scores, the Viterbi paths of every held-out region, the fold models' profiles, and the metrics with molecule-bootstrap confidence intervals.

`hmm/hmm_figures.py` turns those outputs into Fig. 6 (confusion matrices and traceback panels), Fig. 7 and Supp. Fig. 12 (decoded example traces), Supp. Figs. 10–11, and the HMM path-statistics tables (Supp. Tables S9–S12). Each figure is saved as PDF, SVG and 600-dpi PNG, and a `FIGURES.md` lists every file.

```bash
uv run python hmm/hmm_cv_evaluation.py --folds hmm/cv_folds.csv \
    --segments hmm/vrhmm/data/denoise_segment_dynp_parallel_34_BkP_full_pastor_norm_features_clean_1751_4570_min_size_30.pkl \
    --out results/hmm_cv --n-jobs 8
uv run python hmm/hmm_figures.py --cv-dir results/hmm_cv \
    --segments hmm/vrhmm/data/denoise_segment_dynp_parallel_34_BkP_full_pastor_norm_features_clean_1751_4570_min_size_30.pkl \
    --out-dir results/hmm_figures
```

The evaluation takes about 15–20 minutes on 8 cores; the figures take about a minute. Each script's docstring lists its outputs and method details.
